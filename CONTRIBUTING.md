# Contributing to awesome-design-forge

Thanks for contributing! This project follows a strict **branch → PR → review →
squash-merge → tag → release** workflow so every change is reviewable and every
release is traceable.

## Branch & PR workflow (required)

1. **Never commit straight to `main`/`feat/design-forge-v1`.** Create a feature branch:
   ```bash
   git checkout -b feat/<short-slug>      # or fix/<slug> for bugs
   ```
2. Make your change. Keep commits focused.
3. Verify locally before pushing:
   ```bash
   pnpm install
   pnpm gen:brands      # re-bake the ingested-brand registry from design-md/
   pnpm typecheck       # tsc --noEmit
   pnpm test            # vitest (unit + offline compile guarantees)
   ```
   > `ingested.ts` / `ingested-specs.ts` are generated by `pnpm gen:brands` — do not
   > edit them by hand. They are committed so the preview/CLI work without `node:fs`.
4. Push and open a PR:
   ```bash
   git push -u origin feat/<slug>
   gh pr create --base feat/design-forge-v1 --title "feat: ..." --body "..."
   ```
5. CI runs `pnpm gen:brands` + `typecheck` + `test` on the PR. Fix any failures.
6. **Merge** the PR into `feat/design-forge-v1` (squash-merge is fine).
7. Land `feat/design-forge-v1` into `main` via a **second PR** (so `main` reflects the
   work through a real PR, not a direct push), then fast-forward `main`.

## Releases

1. Bump `version` in `package.json` (use the `-design-forge` suffix convention, e.g.
   `1.7.0-design-forge`).
2. Add a `## [x.y.z]` section to `CHANGELOG.md`.
3. Commit on `main`, then tag and push:
   ```bash
   git tag -a v1.7.0-design-forge -m "v1.7.0-design-forge — <summary>"
   git push origin main --tags
   gh release create v1.7.0-design-forge --title "..." --notes "..."
   ```
4. Reference closing issues in the PR/commit (`Fixes #N`).

## Adding brand specs

See [docs/CORPUS.md](docs/CORPUS.md) for the full inventory and the
`design-forge ingest <dir>` re-bake step. Keep specs in canonical DESIGN.md front-matter
shape so they ingest cleanly (no phantom brands).

## Tests

- Unit + offline-build tests live under `src/**/__tests__/` (vitest).
- The Playwright visual-regression suite (`pnpm test:visual`) runs only on a networked CI
  runner (it needs `playwright install --with-deps chromium`). On this build VPS the
  browser system libs are absent — that job is environment-blocked here and is **not** a
  local failure to fake. See [docs/RELEASE-CHECKLIST.md](docs/RELEASE-CHECKLIST.md).

## Human-gated operations

Some operations require human authorization and must **not** be run by automation:
- `pnpm link --global` (issue #3) — needs a human to authorize. See
  **[docs/OPERATOR-pnpm-link.md](docs/OPERATOR-pnpm-link.md)** for the exact,
  ready-to-run command and verification steps.
- Any network/root action to enable the visual-regression browser on this VPS.

When you hit one, stop and surface it rather than executing it.
